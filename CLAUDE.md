# Проект: Бот проверки водителей по чёрному списку (blacklist-driver-bot)

## Контекст и цель

У друга (владелец сообщества/чата водителей в аренде, Одесса) есть база водителей, находящихся в
чёрном списке. Раньше база велась в Excel и доступ к ней продавался вручную. Задача — поднять
полноценный сервис: REST API на Symfony + база данных + Telegram-бот, который по запросу отвечает,
есть ли водитель в чёрном списке, и позволяет искать по имени/фамилии (в перспективе — по номеру
водительского удостоверения). Сейчас база покрывает только Одессу, но заложена возможность
расширения на всю Украину без переделки схемы (регион как отдельная сущность).

Вторая, не менее важная цель: это учебный проект. Карен (владелец, senior PHP/Laravel-разработчик,
10+ лет опыта) готовится к техническому собеседованию, где будет лайвкодинг на Symfony, а
продакшн-опыта с Symfony у него нет (только Laravel/Yii2/Bitrix). Поэтому важно:

- использовать «настоящие» Symfony-подходы (Doctrine ORM, миграции, Console-команды, Security
  с кастомным authenticator, HttpClient для внешних интеграций, PHPUnit KernelTestCase/WebTestCase),
  а не срезать углы через вещи, привычные из Laravel;
- по возможности пояснять архитектурные решения в комментариях/PR-описаниях (например, почему выбран
  Mapped Superclass, а не Single Table Inheritance), чтобы это можно было потом уверенно объяснить
  на собеседовании.

## Исходные данные

Файл `Чорний Список 2025.xlsx`, лист `ЧЕРНЫЙ СПИСОК ВОДИТЕЛЕЙ` (остальные листы — нерелевантный
мусор/реклама СТО, игнорировать). Колонки (реальные, без выдуманных):

1. `Дата` — дата добавления в ЧС (не всегда валидна, встречаются битые значения типа `#VALUE!`).
2. `Кто добавил в ЧС (пострадавшая сторона)` — свободный текст, имя/ник того, кто пожаловался.
3. `Фамилия имя отчество` — ФИО, часто с датой рождения текстом внутри той же ячейки
   (`"Абаржи Дмитрий Петрович 1994"`), иногда задвоено на русском и украинском в одной ячейке,
   разный регистр, лишние пробелы/переносы строк.
4. `обставини` — текст с описанием причины (обстоятельства).

Важно: номера водительских прав в текущих данных **нет**. Поле в схеме нужно предусмотреть
(`licenseNumber`, nullable), но заполняться оно будет только для новых записей вперёд, импорт
из этого файла его не даст.

Данные грязные и требуют нормализации при импорте (парсинг ФИО, извлечение даты рождения из текста,
где это возможно, без выдумывания при отсутствии данных).

## Модель данных (согласовано с Кареном)

- `Region` — справочник регионов (сейчас только «Одесса», заложено под расширение на всю Украину).
- `Driver` — канонический водитель: `lastName`, `firstName`, `middleName` (nullable),
  `licenseNumber` (nullable), `birthDate` (nullable), `region` (ManyToOne → Region). Один водитель —
  одна запись, идентификация по ФИО (+ дате рождения, если есть).
- `AbstractDriverEvent` — Doctrine **Mapped Superclass** (не Single Table Inheritance, это
  сознательный архитектурный выбор, обсуждалось явно): общие поля `driver` (ManyToOne → Driver),
  `reportedBy`, `text`/`reason`, `occurredAt`, `createdAt`.
- `BlacklistEntry extends AbstractDriverEvent` — запись в чёрном списке. У водителя может быть
  несколько записей от разных людей. Возможно добавить `isActive`, если записи можно снимать.
- `DriverHistoryEntry extends AbstractDriverEvent` — любая другая информация о водителе, не
  обязательно негативная (например «предупредили один раз, без занесения в ЧС», «хороший отзыв»).

Поиск: по `Driver` (имя/фамилия, в будущем — номер прав), с подгрузкой связанных
`blacklistEntries`/`historyEntries`.

## Стек и текущее состояние окружения

- Symfony (Symfony CLI 5.20.0 локально у разработчика), Docker-окружение через
  `~/PhpstormProjects/multisite/www/blacklist.localhost/app`.
- Контейнеры: `blacklist.localhost-app` (сама Symfony-app, порт 8096→80) и MariaDB 11.4
  (`blacklist.localhost-mysql`, наружу проброшен `127.0.0.1:13307`, внутри docker-сети — имя
  сервиса и порт 3306, см. `docker-compose.yml` проекта).
- На момент передачи контекста: настраивается `DATABASE_URL` под MariaDB, и была ошибка
  `Environment variable not found: "DEFAULT_URI"` при выполнении `doctrine:database:create` —
  где-то в `config/packages/*.yaml` есть ссылка на `%env(DEFAULT_URI)%` (вероятно
  `framework.yaml` → `router.default_uri`), которую нужно либо найти и задать в `.env.local`
  (например `DEFAULT_URI=http://blacklist.localhost`), либо убрать, если не нужна.
- Требуется `symfony/orm-pack` и `symfony/maker-bundle` (dev) — на момент передачи ещё не
  проверено, стоят ли уже.

## План работ (по шагам)

1. Починить env/DB-конфигурацию (`DEFAULT_URI`, `DATABASE_URL` на сервис MariaDB внутри
   docker-сети, не на `127.0.0.1:13307`), убедиться что `doctrine:database:create` и
   `doctrine:database:list`/подключение работают.
2. Создать сущности `Region`, `Driver`, `AbstractDriverEvent` (вручную, `make:entity` не умеет
   генерить Mapped Superclass из коробки), `BlacklistEntry`, `DriverHistoryEntry`. Сгенерировать и
   прогнать миграции.
3. Написать консольную команду `app:import-blacklist` (компонент Console) на PhpSpreadsheet:
   читает исходный xlsx, парсит ФИО/дату рождения из грязного текста, создаёт/находит `Driver` и
   `BlacklistEntry`, не падает на битых строках (пустые, `#VALUE!`, разделители-заголовки вида
   одиночной буквы `"А"` — это буквенные разделители алфавита в исходнике, не данные, их пропускать).
4. Repository-методы поиска по имени/фамилии (и номеру прав, когда появится) — Doctrine
   QueryBuilder, возможно LIKE или полнотекстовый/триграммный поиск при переходе на PostgreSQL
   в будущем.
5. REST-эндпоинт `GET /api/drivers/search?query=...`, отдаёт водителя + список
   blacklist/history-записей.
6. Авторизация API простым API-ключом через кастомный Symfony Security Authenticator (без OAuth,
   это внутренний сервис для бота).
7. Telegram-бот: `POST /api/telegram/webhook`, принимает апдейты Telegram Bot API, парсит команду,
   дёргает сервис поиска, отвечает через `symfony/http-client` (`sendMessage` в Telegram Bot API).
8. Функциональные тесты (`KernelTestCase`/`WebTestCase`) хотя бы на поиск и импорт.

## Как работать над проектом

- Каренcen ведёт разработку через Claude Code локально в `~/PhpstormProjects/multisite/www/blacklist.localhost/app`.
- Предпочтение — идти маленькими шагами, после каждого шага показывать, что получилось, и
  объяснять архитектурные решения (это часть подготовки к собеседованию, не просто «сделай и всё»).
- Стиль кода — Symfony best practices (типизация, DI через конструктор, тонкие контроллеры,
  бизнес-логика в сервисах, а не в контроллерах или сущностях).
